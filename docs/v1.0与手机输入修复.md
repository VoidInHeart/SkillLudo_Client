## 阶段二 · 手机网页输入修复

旧版实测复现：Android 微信 UA 下，聚焦登录账号后将 412×820 视口高度缩至 550，出现一次 `focusout → focusin`，画布同步缩小。大厅重排暂时移出 EditBox 节点使其失焦，旧的焦点恢复逻辑又打开键盘，形成循环。证据见 `verification/keyboard-baseline-result.json`。

修复包括：

- 手机网页编辑时保留画布的 CSS 宽高，跟随可视视口平移，让输入框完整露在键盘上方；输入框切换不释放尺寸锁。
- Cocos 读取 CSS 容器尺寸，并通过公开的 `screen.windowSize` 接口同步真实尺寸变化，避免只锁 CSS 后渲染缓冲缩小、画面拉伸和输入文字错位。
- 输入期间不重建手机大厅，不在布局后强制恢复焦点；真正收起键盘后恢复布局。手机旋转导致宽度变化时结束编辑一次，保留已输入文本，不自动重开键盘。
- 桌面正常重排仍然生效；浏览器适配仅在 Web 环境启用，微信小游戏继续使用原生输入路径。

### 自动回归与复现

先在不同终端启动 `SkillLudo_Server` 的 `npm run verify:server`（隔离测试服务器 3101）和客户端的 `npm run preview:build`（7459）。客户端执行：

```powershell
npm run check
npm run check:tests
npm test
npm run build:web
npm run verify:keyboard
npm run verify:viewport
npm run build:wechat
npm run verify:wechat
```

`verify:keyboard` 用 Android/iOS 微信 UA 测试登录账号、密码、注册昵称、房间号、技能描述、反馈、聊天；Android 模拟布局视口变化，iOS 模拟仅可视视口变化。高度依次为 550、350、525、480，中文候选输入时额外改为 430。检查持续输入无失焦、渲染缓冲不变、输入文字与棋盘 UI 对齐、键盘上方完整可见、收起后恢复，以及字段切换和聚焦时旋转，共 18 项检查。

线上资源回归可设置 `$env:SKILLLUDO_WEB_URL='http://81.70.145.148'` 后运行 `npm run verify:keyboard`。该测试将 WebSocket 定向本机隔离服务，不会提交真实反馈邮件或操作生产棋局；真实公网双人联机由 `npm run verify:published` 单独验证。

浏览器测试使用 Chromium 和手机 UA/视口模拟，中文候选通过 CDP 模拟；不代表 WebKit、实体手机微信键盘或正式小游戏上传验收。真机复查应覆盖连续输入、切换输入框、中文候选栏、收键盘、旋转及重新编辑。
