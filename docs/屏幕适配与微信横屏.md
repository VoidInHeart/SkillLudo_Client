# 屏幕适配与微信横屏（2026-09-12）

## 问题与修复

用户在微信内打开网页时只能看到被放大的局部，桌面需要缩放到 50%。本地构建复现：1280×800 CSS 像素、DPR 2 时，画布缓冲区正确为 2560×1600，但缺少 CSS 尺寸约束，画布的显示框也变为 2560×1600。手机 DPR 3 在当前引擎中使用上限为 2 的渲染倍率，同样出现两倍显示与裁切。

- Web 模板明确 `#GameCanvas` 的 CSS 宽高为容器的 100%，保留高分屏渲染缓冲区。支持动态视口高度的浏览器使用 `100dvh`。
- 登录页、大厅、房间不再只在初始化时排版；等待 Cocos 视口与设计尺寸更新完成后重新布局，并保持当前页面、房间信息和操作状态。
- 登录/注册表单复用 EditBox 实例，旋转时保留已输入内容。避免销毁输入框后 Cocos Android 延迟 `scrollIntoView` 回调访问已释放元素。房间按钮随房间根节点显示，弹框继续位于其上。

无需把浏览器缩放改为 50%，也不以降低清晰度的方式修复。屏幕方向变化不会重新开始对局或改变棋盘格心。

## 微信内网页与微信小游戏

当前公网 IP 打开的是 Web 页面，微信的网页窗口由微信浏览器控制；支持横屏不意味着画布会自动适配。Web 页面现在分别适配横、竖屏。

微信小游戏可以横屏。项目 `scripts/build-cocos.ps1` 已配置 `orientation = 'landscape'`，构建后的 `build/wechatgame/game.json` 为 `deviceOrientation: "landscape"`。Cocos 官方说明见 [发布到微信小游戏](https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/publish-wechatgame.html)。本次重新构建通过：30 文件、3,575,162 字节，低于 4 MiB；尚未进行微信真机或上传验收。

## 回归与复现

```powershell
npm run check
npm run check:tests
npm test
npm run build:web
# 独立终端启动静态服务
npm run preview:build
# 保证公网游戏服务器可连接；正常加载后使用隔离的表现夹具

```

`verify:viewport` 覆盖 7 种初始环境：桌面 DPR 1/2/1.25、模拟微信 Android 竖屏/横屏 DPR 3、320×568 小屏手机、平板 DPR 2。每种环境都检查首次打开、画布 CSS 边界、控件四角、真实点击注册页签和输入框、旋转后保留同一输入框及文本、大厅/房间重新排版，以及实体骰子和飞机的点击命中。

脚本加载真实页面并完成正常游客连接，随后断开网络，使用权威生成的棋局夹具记录命令，不创建测试账号或向生产提交测试棋局。该脚本验证显示和点击坐标，不冒充真实手机或真实网络移动。已有 `verify:browser` 另通过真实双人 WebSocket 对局、骰子/飞机点击、重连、视角、校准和动作落点验证。22 项客户端回归与类型检查通过；服务端本轮未修改。
